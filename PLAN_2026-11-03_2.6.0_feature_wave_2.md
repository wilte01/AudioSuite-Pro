## 2. F-E2 — Peak/true-peak normalisation mode

### 2.1 Design

A second target mode beside LUFS, in the same engine.

- `NormaliseParams` gains `target_mode: Literal["lufs", "peak"] = "lufs"` and
  `target_peak_dbtp: float = -1.0`. Rename nothing: `mode` may already mean
  something else, so **read the field first** and use a distinct name.
- Application policy, in order:
  1. measure the file's sample peak and true peak (`audio_probe.measure_levels`);
  2. `gain = target_peak - true_peak`; if `abs(gain) <= tolerance` do nothing;
  3. apply the static gain; if the resulting sample peak would exceed 0 dBFS,
     insert the limiter instead of a clamp and report `limited=True`;
  4. verify after render and report measured sample peak, true peak and applied
     gain.
- The limiter is the existing pedalboard chain (or FFmpeg `alimiter` in the
  pydub path); do not write a second limiter.
- Tags and depth: reuse the normaliser's existing copy/depth path.

### 2.2 Surface

`refine --target-mode peak --target-peak -1.0`; Refinery setup normalise panel
gets a mode selector; driver card; presets round-trip both fields with defaults
that keep LUFS behaviour.

### 2.3 Acceptance and tests

- `audio_refinery/tests/test_peak_normalise.py`: decoded sample peak **and**
  true peak at or below the target within **0.2 dB**; no sample at full scale
  beyond the ceiling; no clipping count > 0 from `astats`.
- Relative dynamics preserved where possible: a file that needs only a static
  gain is not limited (assert `limited=False` and gain reduction 0 in the
  limiter stage).
- Tags preserved on MP3/FLAC/M4A; depth preserved on WAV/AIFF.
- Dry run writes nothing and reports the projected gain and ceiling.

### 2.4 Effort and risk

1-2 weeks. Risk: true-peak measurement vs sample-peak confusion — the guide and
the result line must name which target was met, and the test must assert both.

## 3. F-E7 — Tag copy/template

### 3.1 Design

- New `audio_suite_shared/tag_templates.py`:
  - `TagTemplate` frozen dataclass: `name`, `fields: dict[str, str]`, `source`.
  - Storage in the **shared suite config** under `tag_templates`
    (`suite_config.load_value`/`save_value`), not a new tool-local JSON file.
  - `template_from_file(path, fields) -> TagTemplate` reads through
    `TagFieldEngine.read_fields`.
- `tag_editor` gains:
  - "Copy fields from reference file" — choose file, choose fields, preview a
    diff (`TagFieldEngine.diff`), apply;
  - "Save current values as template" / "Apply template";
  - dry-run diff listing per-field before/after and untouched fields explicitly
    marked unchanged;
  - one undo batch per apply, so Undo Tag Edits restores the snapshot.
- CLI: `tag-edit --copy-from REF --fields title,artist,album` (verify the command
  name against `audiosuite --help` before wiring), plus `--dry/--live`.

### 3.2 Acceptance and tests

- `tests/test_tag_copy_template.py`: written tags read back equal on MP3/FLAC/M4A/WAV.
- Untouched fields are unchanged at the raw-tag level (compare the raw tags dict,
  not just canonical fields).
- Undo restores the exact pre-edit raw values on one container per handler family.
- Dry run: file `st_mtime_ns` and decoded tags unchanged; the diff names exactly
  the fields that would change.
- A template naming a field the container cannot store is refused with the named
  reason, not silently dropped.

### 3.3 Effort and risk

1-2 weeks. Risk: template fields that are container-specific (`TXXX:SUITE_*`
versus Vorbis keys) — the engine's `FIELD_RULES` must be the only mapping, and a
test must assert no second table appears.

## 4. F-E8 — CUE export from a folder

### 4.1 Step 0: prove what already exists

Read `audio_suite_shared/cue_cli.py::cue_generate_cli` and `_scan_audio_files`
before writing code. Two outcomes:

- **If `audiosuite cue generate` already exports a folder**, this item is:
  an acceptance lock (below), a GUI surface, a driver card if the suite's UX
  expects one, and the guide. Do not rebuild it.
- **If it only renders a CUE for the CD ripper**, add
  `audio_suite_shared/cue_export.py::build_folder_cue(paths) -> str` reusing
  `cue_generator.build_cue`/`ms_to_frames`/`format_msf` and durations from
  `audio_probe.probe_stream`, plus a `--recursive` flag.

### 4.2 Rules

- Durations come from the file header, never guessed; a file whose duration
  cannot be measured is refused (the audit's acceptance rule).
- Track numbers from tags where present, else file order; a duplicate number is
  refused rather than renumbered silently.
- Offsets are cumulative frames (75 per second); the file is written UTF-8 with
  no BOM and CRLF line endings, because `cue_parser` and Windows tools both
  expect that.
- `--force` is required to overwrite an existing `.cue`.

### 4.3 Acceptance and tests

- Generated text parses back through `audio_suite_shared.cue_parser` with
  identical offsets and file names.
- A folder of three known-duration files yields three `TRACK` entries whose
  cumulative offsets match the measured durations within 1 frame.
- Missing duration is refused with a named reason and no file written.
- A duplicate track number is refused.

### 4.4 Effort and risk

3-5 days if the CLI already exists; 1 week if not. Risk is scope: CUE export is
in `2.6.0`, CUE *splitting* by silence is `2.5.0`'s splitter; they must not merge
into one change.

## 5. F-E9 — Exact-duplicate mode

### 5.1 Design

Two hashes, two questions, one grouped report:

- `duplicate_finder/core/exact.py`:
  - `file_sha256(path)` — raw bytes. Finds byte-identical and renamed copies.
  - `pcm_sha256(path)` — decoded PCM at the source's sample rate and channel
    count, packed `s32le`, so a metadata-only edit does not defeat the match and
    a different bit depth does. Document that policy; offer
    `--exact-ignore-depth` only if a user-visible need appears (not in this
    release).
- `ScanSettings` gains `exact_mode: Literal["off", "only", "also"] = "off"`.
  `"also"` reports exact groups in the same run as perceptual groups, labelled
  separately; `"only"` skips fingerprinting entirely.
- Cache: extend `fingerprint_cache` with `file_sha256` and `pcm_sha256` columns
  and a schema-version migration following the `batch_undo` migration pattern.
  Freshness stays `(mtime, size)`; a schema bump must not silently recompute
  every row without saying so in the report.
- CLI `duplicates --exact only|also|off`; driver card toggle; results rows get an
  `[EXACT]` token distinct from `[FINGERPRINT]`.
- Dispositions apply unchanged to exact groups (quarantine/delete/stub), because
  the keeper rule already prefers lossless/higher quality.

### 5.2 Acceptance and tests

- Fixtures: a renamed byte-identical copy (exact group), a re-encoded copy at a
  different bitrate (not exact, may be perceptual), a different master with an
  EQ change (neither), and a copy whose only change is a tag edit (exact by
  `pcm_sha256`, not by `file_sha256`). All four behave as specified.
- The cache stores and reloads both hashes; a stale `(mtime, size)` recomputes
  once.
- A dry run moves nothing and reports both group kinds.
- `--exact only` on a folder with no fingerprints cached performs no ffmpeg
  fingerprint call (assert the call count).

### 5.3 Effort and risk

1-2 weeks. Risk: PCM hashing 1,000 files is expensive (decode + hash). Mitigate
with the existing worker pool, a per-file cache, and a documented cost in the
guide; do not hash to find a perceptual duplicate.

## 6. F-E10 — Artwork extraction and missing-art report

### 6.1 Design

- `audio_suite_shared/tag_helper_art.py`:
  - `extract_artwork(path) -> tuple[bytes, str] | None` returning the embedded
    stream and its mime type, read through the handler (not a second mutagen
    path);
  - `write_artwork_sidecar(folder, *, name="cover", force=False) -> Path | None`
    writing `.jpg`/`.png` by mime, refusing to overwrite without `force`.
- New CLI group `audiosuite artwork` with `extract` (batch, recursive optional)
  and `report` (files with no art, and art over a size/dimension threshold).
- `library_stats` CSV/JSON gains `has_art`, `art_width`, `art_height`,
  `art_bytes` columns, populated from the same extraction; no new tool, no new
  window.
- Formats without an artwork container (e.g. raw `.aac` ADTS) report cleanly
  (`has_art=False`, no error).

### 6.2 Acceptance and tests

- Extracted bytes hash-equal the embedded stream on MP3 (APIC), FLAC (picture
  block), M4A (`covr`), and WAV/AIFF (ID3 APIC) fixtures.
- A file with no art returns `None` and writes nothing.
- `force=False` leaves an existing `cover.jpg` untouched (mtime and bytes).
- The report's counts equal the fixtures' known art presence.
- Read-only run changes no file (`st_mtime_ns` tree snapshot).

### 6.3 Effort and risk

3-5 days. Risk: mime detection (some containers claim `image/jpeg` for PNG
data) — sniff magic bytes and write the extension from the bytes, not the
declared mime, then assert it in the test.

## 11. Follow-on accepted 2026-11-09 — PCM loudness (D-8 closure)

Added after the WAV/AIFF investigation this session prompted. The refusal was
never a format policy: the 1.0 gap fix (`PLAN_gap_analysis` 1.1) replaced a
*silent MP3 fallback* with a hard refusal, and the "if intended, add
`.wav`/`.aiff`" half was never taken. Peak targets wrote those containers (F-E2)
while LUFS and album mode refused them, so one tool gave two answers for one
file; album mode also inherited the gap, which left WAV rips un-normalisable.

### 11.1 Design

- `.wav`, `.aiff` and `.aif` resolve their encoder from `FORMAT_MATRIX`
  (`audio_formats.ffmpeg_encoder_args`) rather than gaining a tuned
  `_FORMAT_CODEC` entry.
- `_depth_args` re-pins the source's integer depth before the encode
  (`preserve_depth_params`), because FFmpeg's WAV/AIFF muxers write 16-bit PCM
  whatever came in — the F-10 class, here in the normaliser itself.
- `apply_static_gain` pins depth for any integer-PCM destination, so album mode
  inherits the fix without a second flag.
- The refusal's format list is derived (`NORMALISE_EXTENSIONS`,
  `normalise_format_display`), so it cannot name a format the stage does not
  write or omit one it does.

### 11.2 Acceptance and tests

- 24-bit WAV and 24-bit AIFF: decoded depth, rate, channels and measured
  integrated loudness, read back from the written file.
- 16-bit WAV round-trips at 16 bits.
- Command shape: the effective `-c:a` is the depth pin's PCM codec and `-ar` is
  the source's rate.
- Album mode: a 24-bit WAV album moves by its plan's gain and keeps 24 bits.
- Refinery `process_file`: a 24-bit WAV normalise-only run is DONE, reaches
  -23 LUFS ±0.7 and keeps 24 bits.

### 11.3 The skip shape (D-12)

A container with no normalise encoder (`MP4`, `WMA`, `AAC`) is reported per file
as a skipped stage naming the reason and the formats the stage does write,
instead of raising `AudioProcessingError` after the other stages had run. The
skip is decided once, before the stage work, so Enhancement's output gain is not
suppressed for a normalisation that will not happen, and the dry run predicts the
same skip. The read-only formats keep their earlier skip path.
