## 2. F-S1 — Parametric EQ stage

### 2.1 Design

- New pure module `audio_suite_shared/dsp_eq.py`:
  - `@dataclass(frozen=True) EqBand`: `kind: Literal["lowshelf","highshelf","peaking","highpass","lowpass"]`,
    `freq_hz`, `gain_db`, `q`.
  - `@dataclass(frozen=True) EqSettings`: `bands: tuple[EqBand, ...]` (max 8),
    `bypass: bool`; validation refuses out-of-range frequencies (20 Hz-20 kHz),
    gains (±24 dB) and Q (0.1-18).
  - `build_eq_plugins(settings) -> list[Any]` returns pedalboard plugins
    (`LowShelfFilter`, `HighShelfFilter`, `PeakFilter`, `HighpassFilter`,
    `LowpassFilter`); `apply_eq(audio, settings, sample_rate)`; and
    `response_curve(settings, freqs) -> np.ndarray` computed from the same
    coefficients, not from a second formula.
- Refinery integration: `StageConfig` gains an `eq: EqSettings | None = None`
  stage with its own enable flag in `REFINERY_STAGES` (arg_builder's frozen
  tuple grows, and `master_driver/tests/test_runner.py`'s field-to-stage-name
  assertion is the lock). CLI `refine --eq-band "peaking,1000,3.0,1.0"` repeated;
  driver card gets a compact band editor; GUI gets a band table plus a matplotlib
  response curve.
- Presets: `_to_dict`/`_from_dict` serialise bands; the shipped default file gains
  an empty band list, and `TestShippedDefault` must be updated in the same
  commit (that test is the contract, not an obstacle).

### 2.2 Acceptance and tests

- Response measurement: for each band kind, render a logarithmic sine sweep (or
  measure a set of single-frequency tones), compute the transfer function, and
  compare against `response_curve` within **0.5 dB** at 1/3-octave points.
- Unity bypass is **bit-transparent**: `apply_eq` with `bypass=True` returns an
  array equal to the input (`np.array_equal`), and the written file decodes to
  identical samples.
- A band with 0 dB gain and any Q is transparent within 1 LSB.
- Depth/sample-rate preserved through the pipeline; tags preserved.
- `response_curve` and the render use the same coefficients — assert the render
  matches the curve, not the curve matches itself.

### 2.3 Risk

The pedalboard filter classes differ in parameter names (`cutoff_frequency_hz`
vs `frequency_hz`) between versions; pin behaviour with a test that constructs
each plugin and inspects its `__class__.__name__`, and record the installed
pedalboard version in the test's failure message. Never guess a parameter name.

## 3. F-S2 — Controllable dynamics stage

### 3.1 Design

- New `audio_suite_shared/dsp_dynamics.py`:
  - `CompressorSettings(threshold_db, ratio, attack_ms, release_ms, makeup_db, knee_db)`.
  - `LimiterSettings(ceiling_dbtp, lookahead_ms, release_ms)`.
  - `GainReductionReport`: per-block max/mean gain reduction, total reduction,
    output integrated LUFS and true peak.
  - `apply_dynamics(audio, compressor, limiter, sample_rate) -> tuple[array, GainReductionReport]`
    using pedalboard `Compressor` + `Limiter`; the report is computed from the
    gain envelope, and verified against measured output level.
- Refinery stage `dynamics` with enable flag, CLI flags
  (`--comp-threshold`, `--comp-ratio`, `--comp-attack`, `--comp-release`,
  `--comp-makeup`, `--limiter-ceiling`, `--limiter-lookahead`), driver card and
  GUI panel with a gain-reduction meter fed from the dry-run projection.
- Dry run renders to memory (or a temp file) and reports the projection without
  writing the source.

### 3.2 Acceptance and tests

- Static gain reduction: a steady 1 kHz tone at threshold+6 dB with ratio 4:1
  measures output level within **0.5 dB** of the expected reduction.
- Limiter: a signal driven 6 dB over the ceiling measures true peak at or below
  the ceiling within **0.2 dB**, with no overshoot and no sample above it.
- Output LUFS and TP in the report equal the post-render measurement within
  0.2 dB.
- Attack/release behaviour: a step fixture shows gain reduction moving in the
  expected direction within one attack/release time constant (assert the
  direction and rough magnitude, not a brittle curve).
- Makeup gain applied after compression, proven by output level.

### 3.3 Risk

A "compressor" tested only by its settings read-back is the exact defect class
the suite bans. The tone test is mandatory, and `limited`/`report` values must be
recomputed from the rendered audio, never returned from the request.

## 4. F-S4 — Pitch/time manipulation (new tool `pitch_time`)

### 4.1 Why a new tool

Time-stretch and pitch-shift are whole-file transforms with their own settings
and batch semantics, not repair stages: applying them inside the Refinery would
make the file length a stage output and break the pipeline's "same duration"
assumptions used by declick/trim. A separate tool keeps the Refinery invariant.

### 4.2 Design

- New `audio_suite_shared/dsp_time_pitch.py`:
  - `time_stretch(audio, rate, *, preserve_pitch=True)` (librosa `effects.time_stretch`
    or pedalboard `time_stretch`);
  - `pitch_shift(audio, semitones, *, formant_preserve: bool)`;
  - `change_tempo(audio, factor)` and `change_pitch(audio, semitones)`;
  - every function returns the processed array plus `original_seconds` and
    `processed_seconds`, so the report never recomputes from the request.
- New package `pitch_time/`: `core/engine.py`, `core/models.py`
  (`PitchTimeSettings(mode: "tempo"|"pitch", rate, semitones, quality)`),
  `cli.py` (`audiosuite pitchtime --rate 1.1` / `--semitones -2`),
  `app.py` + `ui/*`, `utils/cli_args.py`, `tests/`.
- Sample-rate and channel handling delegated to `analysis_loader`'s decode and
  the shared write path; refuse a source the loader cannot decode rather than
  converting silently.
- `tool_id = "pitch_time"`, `pyw = Pitch_Time.pyw`. Full registration per the
  index §4.4.

### 4.3 Acceptance and tests

- Duration ratio: a 1.000 s 440 Hz tone at `rate=1.25` decodes to 0.800 s ± 1 ms
  with its frequency unchanged within 1 cent.
- Pitch: `semitones=+12` on a 440 Hz tone decodes to 880 Hz within 1 cent with
  duration unchanged (± 10 ms, depending on the algorithm).
- Original and processed durations reported and equal to measured values.
- Artefact sanity on a vocal fixture: spectral centroid and harmonic-to-noise
  ratio move by less than a stated bound versus the source (an objective test
  that a naive resample fails, because resampling changes both duration and
  pitch together).
- Dry run writes nothing.

### 4.4 Risk

Algorithm choice: librosa's phase-vocoder and pedalboard's `time_stretch` differ
audibly and in duration rounding. Pick one as the default, measure both on the
tone fixture, and record the choice plus its measured numbers. Do not expose a
"quality" switch in this release unless both are tested.

## 5. F-S5 — Album gain staging with per-track report

### 5.1 Design

Extends F-E1 rather than replacing it.

- `AlbumPlan` (F-E1) gains per-track rows: measured integrated LUFS, measured
  true peak, applied gain, `limited` flag, and deviation from the album target.
- `audio_refinery` writes a per-track table into the run report (the results tab
  and the CSV/JSON export already exist for file rows) with columns:
  `file, album_lufs, track_lufs, track_tp, applied_gain_db, limited, deviation_lu`.
- A user-set window (`--album-deviation-lu`, default 3.0) flags tracks whose
  deviation after limiting exceeds it, and the run outcome carries a caveat
  naming them (the established `run_outcome` mechanism).

### 5.2 Acceptance and tests

- Album loudness target met within **0.5 LU**; every track's reported loudness
  equals its decoded measurement within **0.1 LU**; applied gain equals
  `after - before` within **0.05 dB**.
- A track that had to be limited is flagged, its deviation reported, and the
  caveat names it.
- The exported CSV contains one row per track with the exact measured values
  (parse the CSV in the test, do not inspect the in-memory plan).
- A dry run produces the same table and writes no audio.

### 5.3 Risk

The report and the audio can diverge if the report is built from the plan while
the render applies a tolerance-based no-op. Build every reported number from the
decoded output, and assert that in the test.

## 6. F-S7 — Audio QC / forensics report

### 6.1 Design

- New `library_stats/core/qc.py` (pure, no Tk):
  - `QcMetrics`: integrated LUFS, LRA, true peak, sample peak, crest factor
    (DR), DC offset per channel, phase correlation (stereo only), clipped-sample
    count, dropout count, plus the probe's `StreamInfo`.
  - `measure_file(path) -> QcMetrics` built on `audio_probe`.
- `library_stats` gains an opt-in QC pass (`--qc`, `--qc-json`, `--qc-csv`,
  `--qc-workers`) and four CSV/JSON columns per metric group; the HTML report
  gets a QC section with the worst offenders.
- Refusals: a read-only or undecodable file reports `qc_error` with the reason
  and does not fail the scan; a mono file reports phase correlation as `null`
  with a note, never `0.0`.
- Read-only guarantee: QC never writes audio or tags, and never opens a file for
  append.

### 6.2 Acceptance and tests

- Agreement with FFmpeg on a fixture corpus: integrated LUFS within **0.1 LU**,
  true peak within **0.2 dB**, LRA within **0.5 LU**, DC offset within 0.0001.
  The reference values are produced by an explicit `ebur128`/`astats` invocation
  in the test, and a divergence is a test failure with both numbers printed.
- Clipped-sample count matches a fixture built with N deliberately clipped
  samples; dropout count matches a fixture with M digital-silence gaps.
- Phase correlation: +1.0 for identical channels, -1.0 for inverted, ~0 for
  uncorrelated noise, `null` for mono.
- Read-only: tree `st_mtime_ns` snapshot unchanged after a full run.
- No new direct `subprocess`; all FFmpeg through the probe.

### 6.3 Risk

"DR" has several definitions (crest factor vs the TT-DR meter). Choose crest
factor, say so in the column header and the guide, and do not label it "DR"
without qualification — otherwise every user compares it to a different meter.

## 7. F-S9 — Loudness-matched A/B audition

### 7.1 Design

- `audio_suite_shared/ui_audition.py` `AuditionMixin` gains
  `prepare_matched_audition(original, result, *, mode="momentary", blind=False)`:
  - measure both files' momentary loudness (short-window integrated via
    `audio_probe`), compute the difference, and apply the **quieter-to-louder**
    or **louder-to-quieter** rule chosen by the user (default: attenuate the
    louder file, never boost past 0 dBFS);
  - cache the gain-matched preview as a temp WAV so playback does not re-render;
  - `blind=True` randomises the A/B labels per run and records the mapping only
    after the user chooses, so the report can say which was which.
- Labels: "Original (level matched)" / "Result (level matched)", and an explicit
  note when the match was capped by the 0 dBFS rule.
- No writes to the source files during preview; temp files cleaned with the
  existing `_cleanup` path.

### 7.2 Acceptance and tests

- Render both previews to disk in the test and measure their loudness: the
  difference is within **0.1 LU** of the target match.
- Blind mode returns labels that do not reveal the mapping (assert the label
  strings are `A`/`B` and the mapping is only exposed by the result call).
- No source file is modified (`st_mtime_ns` snapshot).
- Playback itself is not asserted (no audio device in CI); `can_audition` and
  the prepared file path are asserted instead, and the limitation is recorded.

### 7.3 Risk

"Louder wins" is the defect this fixes, so the test must measure the previews,
not the gain value applied. Do not gain-match by peak — a peak-matched quieter
master still loses.
