# AudioSuite-Pro

AudioSuite-Pro is a Windows-first audio workbench of 27 first-party tools
that share one driver, one command line and one registry: tag enrichment
(BPM, key, mood, lyrics, album art, ReplayGain, genre), DSP repair and
conversion (loudness normalisation, hum/click removal, silence trimming,
format conversion, enhancement), library utilities (CD ripping, tag-based
reorganisation, statistics) and a full multi-stage refinery pipeline. Every
tool has a generated user guide, a card in the Master Driver control panel,
and an `audiosuite` CLI subcommand where one exists.

## Prerequisites

* **Python 3.10 or newer** (`requires-python = ">=3.10"` in `pyproject.toml`;
  CI verifies 3.10 and 3.12; development runs on 3.14).
* **ffmpeg and ffprobe on `PATH`.** The suite shells out to both:

  * ffmpeg — *decodes and encodes the audio formats the suite reads and writes*
  * ffprobe — *reads stream metadata (duration, codec, bitrate) for analysis tools*

  Install commands:

  ```
  Windows: winget install Gyan.FFmpeg
  macOS:   brew install ffmpeg
  Linux:   sudo apt install ffmpeg
  ```

  A missing binary is reported as a **warning at launch**, not a block:
  the `.pyw` launchers show which executables are missing and how to install
  them, and tools that do not shell out to ffmpeg keep working.

### Platforms

AudioSuite-Pro is Windows-first: the `.pyw` launchers, drive-letter handling
in the CD Ripper, ACL hardening and other Win32-specific subsystems target
Windows. The command-line core (`audiosuite ...`) and the shared decode/DSP
paths in `audio_suite_shared` do not depend on Windows-only APIs and are
exercised by the test suite. Anything beyond "Windows, GUI and CLI" is
**unverified** — a declared, tiered support matrix (portable core /
Windows-only / untested) is tracked separately.

## Installation

Clone the repository, then sync the environment with the project's extras
(`dev` = the test/lint/typecheck gate, `analysis` = the librosa stack,
`cd-ripping` = discid/MusicBrainz for the CD Ripper):

```
git clone <this-repository> AudioSuite-Pro
cd AudioSuite-Pro
uv sync --extra dev --extra analysis --extra cd-ripping
```

Without `uv`, the equivalent is:

```
python -m pip install -e ".[dev,analysis,cd-ripping]"
```

### One-command smoke test

```
uv run audiosuite --help
```

And a first working tool, in analysis-only mode (writes nothing):

```
uv run audiosuite normalise "C:\path\to\music" --dry
```

The GUI path is the root launcher `Master_Driver.pyw` (a control panel with a
card per tool); every tool also has its own `<Tool>.pyw` launcher.

## Architecture

* **`audio_suite_shared/`** — the shared layer every tool builds on:
  manifest/plugin registration (`tool_plugin.py`), Tk styling and help
  launchers (`styles`, `ui_helpers`, `platform_utils`), secure subprocess
  execution (`secure_subprocess.py`, ffmpeg/ffprobe allowlist), startup
  preflight and declared system requirements (`preflight.py`,
  `system_requirements.py`), suite-wide JSON config (`suite_config.py`),
  the shared audio decode path for the analysis family
  (`analysis_loader.py`), and the exception hierarchy.
* **`BaseFileProcessor`** (`audio_suite_shared/file_processor_base.py`) —
  the common per-file workflow: progress callbacks, per-file error
  isolation (one bad file never aborts a batch), undo snapshots through
 `BatchUndoLog`, and the in-place DSP write path. Tools plug in a DSP
  callable and inherit the workflow.
* **Per-tool shape** — each `<package>/` contains `app.py` (Tk
  application), `core/` (DSP/analysis logic) and `cli.py` (click command
  registered on the shared `audiosuite` group); GUI-only extras live in
  `ui/`.
* **`master_driver/`** — the control panel: a card per tool
  (`ui/cards/{tool_id}_card.py`, the manifest `id` is the filename key), an
  arg builder (`runner/arg_builder.py`), and a batch orchestrator with an
  explicit dependency graph so parallel runs keep enrich → utility ordering.
* **Undo** — batch tag edits record an undo snapshot (`Undo_Tag_Edits.pyw`
  replays them); the configuration, keys and history live in the shared
  `audio_suite_config.json`.
