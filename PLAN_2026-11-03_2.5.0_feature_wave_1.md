## 2. F-E1 — Album-mode loudness normalisation

### 2.1 Design

One engine, two consumers.

- New `audio_normalizer/core/album.py`:
  - `@dataclass(frozen=True) AlbumPlan`: `album_lufs`, `target_lufs`,
    `true_peak_ceiling`, `gains: dict[str, float]`, `limited: dict[str, bool]`,
    `album_true_peak`, `notes: tuple[str, ...]`.
  - `build_album_plan(paths, target_lufs, true_peak_ceiling, tolerance) -> AlbumPlan`:
    1. measure the folder once as a concatenated stream (`audio_probe.measure_album_loudness`);
    2. probe each file for its own true peak;
    3. `gain = target - album_lufs` for every file;
    4. if `peak_i + gain > ceiling`, reduce **that file's** gain to the ceiling
       and mark it `limited` — never touch the others, and never silently
       re-target the album;
    5. if `abs(target - album_lufs) <= tolerance`, return zero gains and a note,
       matching the per-file no-op rule.
  - `apply_album_gain(path, gain_db, *, output, dry_run)` uses the existing
    normaliser filter chain with a single static gain and the depth-pinning
    export arguments; when `limited` a limiter is inserted rather than a clamp.
- The Refinery needs a **pre-pass** because its workers are per file today:
  `audio_refinery/core/file_processor.py::run_pipeline` builds the plan once,
  before workers start, and passes `plan` into each worker;
  `pipeline._run_normalise_stage` consumes `plan.gains[path]` instead of
  measuring. `StageConfig.normalise_params` gains `album_mode: bool`.
- The stage-only `audio_normalizer` package exposes the same engine; it does not
  get a window (no window exists since 2.3.1).

### 2.2 Surface

| Surface | Change |
|---|---|
| CLI (`refine`) | `--album-mode / --no-album-mode`, default off; `--target-lufs`, `--true-peak` already exist |
| Driver | `audio_refinery` card: "Album loudness" checkbox; `arg_builder.build_refinery_args` emits `--album-mode` |
| GUI | `audio_refinery/ui/setup_tab.py` normalise panel: checkbox + a read-only line showing the planned album gain after a measure pass |
| Presets | `refinery_settings.default.json` and `utils/settings.py` `_to_dict`/`_from_dict` gain the field, with a default that preserves current behaviour |

### 2.3 Acceptance and tests

- `audio_normalizer/tests/test_album.py`: synthetic three-track album with
  deliberately uneven levels. Decoded per-track gain equals the album gain
  within **0.1 dB**; measured album loudness within **0.5 LU** of target;
  true-peak ceiling held on every track.
- `audio_refinery/tests/test_album_mode.py`: the plan is built once (assert one
  concatenated measurement for N files, not N); a limited track reports its
  reduction; a dry run writes no file and reports the planned gain per file.
- No-op rule: an already-on-target album produces zero writes and a DONE result
  with measurements.
- Cross-tool: the album loudness the plan reports equals
  `replaygain_analyzer`'s album measurement within 0.1 dB on the same folder.

### 2.4 Effort and risk

1-2 weeks. Risk: the Refinery's no-op/write rules (`tests/test_pipeline_noop.py`)
are strict — an album gain of 0.0 dB must not rewrite a file. Reuse the existing
tolerance branch rather than a second threshold.

## 3. F-E3 — Exact time-range extract/trim

### 3.1 Design

Extend the existing trim stage rather than adding a tool.

- `audio_refinery/core/models.py::TrimParams` gains
  `mode: Literal["silence", "exact"] = "silence"`, `start_ms: int | None`,
  `end_ms: int | None`, `duration_ms: int | None`, `copy_mode: bool = False`.
  Exactly one of `end_ms`/`duration_ms` may be set; validation raises the typed
  config error otherwise.
- `pipeline._run_trim_stage` dispatches: `silence` keeps today's behaviour;
  `exact` slices by sample offset.
- Two write strategies:
  - **copy mode** (`--trim-copy`): FFmpeg `-ss <start> -to <end> -c copy`, only
    for containers that tolerate it (MP3, FLAC, M4A/MP4, OGG/Opus). Report the
    **actual** cut points read back with `ffprobe`, because a copy lands on frame
    boundaries.
  - **re-encode** (default): sample-accurate slice through the existing write
    path, depth pinned by `audio_formats.preserve_depth_params`.
- Collisions: `--trim` is not currently a flag (`--stages trim` selects the
  stage; `--threshold` configures it), so `--trim-start/--trim-end/--trim-duration/--trim-copy`
  are free. Verify against `refine --help` before wiring the driver.

### 3.2 Surface

CLI `refine` flags; Refinery setup panel gets a mode radio (Silence / Exact) and
three entries; driver card gets the same; presets round-trip the fields.

### 3.3 Acceptance and tests

- `audio_refinery/tests/test_exact_trim.py`:
  - re-encode: output duration within **1 ms** of the requested range, measured
    from the decoded file;
  - copy mode: audio packets inside the kept range are byte-identical to the
    source's (`ffprobe -show_packets` payload hashes), duration within one frame,
    and the reported cut points equal the measured ones;
  - tags and embedded art survive both modes;
  - depth preserved on a 24-bit WAV source (the F-10 lesson);
  - a range past end-of-file is refused before writing.
- A dry run writes nothing and reports the cut points.

### 3.4 Effort and risk

1 week. Risk is copy-mode expectations: the plan must document "frame-accurate,
not sample-accurate" in the guide and in the result line, or users will report
the frame offset as a bug.

## 4. F-E4 — Silence-based track splitter (new tool `track_splitter`)

### 4.1 Why a new tool

`cue_split` splits an *image by a known CUE*; this item finds boundaries that are
not known. The workflow (scan -> review boundaries -> split -> optional CUE) is
its own batch operation with its own settings, results and undo, so it is a new
tool, not a Refinery stage (a stage cannot write N files per input file).

### 4.2 Design

| Layer | File | Content |
|---|---|---|
| Detection | `track_splitter/core/detector.py` | FFmpeg `silencedetect` through `run_secure_subprocess`; returns `Gap(start_ms, end_ms, duration_ms)` runs above/below a threshold |
| Planning | `track_splitter/core/models.py` | `SplitSettings(min_silence_ms, silence_db, min_track_ms, boundary: "midpoint"\|"start"\|"end", naming_pattern)`, `Track(start_ms, end_ms, title, number)` |
| Writing | `track_splitter/core/splitter.py` | Sample-accurate slice per track through the shared write path; no sample loss: boundary list is contiguous and covers the source |
| CUE | `track_splitter/core/cue.py` | `cue_generator.build_cue` from tags + measured offsets |
| Naming | `track_splitter/core/naming.py` | Pattern render (`{album}/{track} - {title}`); a pure function, tested without Tk |
| CLI | `track_splitter/cli.py` | `audiosuite split --min-silence --silence-db --naming --cue --dry/--live --json` |
| GUI | `track_splitter/app.py`, `ui/setup_tab.py`, `ui/results_tab.py`, `ui/processing_tab.py` | Shared shell (`SuiteApp` if `2.4.3` landed; otherwise `BaseSuiteApp` + `ui_common` builders) |
| Handshake | `track_splitter/utils/cli_args.py` | Declares `VALUE_OPTIONS`; uses the shared handshake |
| Undo | `splitter.py` | New-file batch recorded through `active_batch`; a dry run records nothing |

Registration: all eleven steps in `PLAN_2026-11-03_audit_sequencing.md` §4.4.
`tool_id = "track_splitter"`, `pyw = Track_Splitter.pyw`.

### 4.3 Acceptance and tests

- Track count equals the number of detected runs (plus one for the tail).
- Boundaries equal the detected runs at the chosen boundary rule, within 1 ms.
- No sample loss: the concatenation of output tracks plus the discarded gaps
  equals the source duration within 1 ms, and a synthetic fixture with a known
  tone per segment decodes the expected tone in each output.
- CUE round-trips through `audio_suite_shared.cue_parser` with identical offsets.
- A single-track source produces one file and a clear "no gap found" line.
- Dry run lists planned tracks and writes nothing.

### 4.4 Effort and risk

1.5-2 weeks including registration. Risk: `silencedetect`'s threshold semantics
(dB relative to full scale, run length) must be stated in the guide and used
consistently; the detector's own tests pin it.

## 5. F-E5 — Join/concat with optional crossfade (new tool `audio_joiner`)

### 5.1 Design

| Layer | Content |
|---|---|
| Compatibility check | `audio_joiner/core/compat.py`: sample rate, channels, codec, container per input via `audio_probe.probe_stream`; identical => concat demuxer; otherwise re-encode **all** inputs to the first file's parameters and say so in the report |
| Join | `audio_joiner/core/concat.py`: FFmpeg concat demuxer with `-c copy`; gaps as generated silence inserted in the list |
| Crossfade | `audio_joiner/core/crossfade.py`: FFmpeg `acrossfade` (equal power) for a chosen overlap; duration arithmetic is explicit (`sum - overlaps + gaps`) |
| Tags | `audio_suite_shared.tag_field_engine` applying the first file's tags (default) or a template (F-E7 arrives later; until then first-file only) |
| CLI | `audiosuite join --order a,b,c --crossfade-ms --gap-ms --output --dry/--live` |
| GUI | Reorderable list, per-file duration readout, output entry; `SuiteApp`-based |

`tool_id = "audio_joiner"`, `pyw = Audio_Joiner.pyw`.

### 5.2 Acceptance and tests

- Duration equals `sum - overlaps + gaps` within one frame.
- No DC step at a join: measured maximum absolute sample delta within ±5 ms of
  each boundary is not an outlier against the surrounding 50 ms (a synthetic
  two-tone fixture makes this measurable).
- Sample rate and channel count consistent across the output and equal to the
  declared policy.
- Tags verified after decode on MP3/FLAC/M4A/WAV.
- A mixed-parameter set is either re-encoded with an explicit report line or
  refused; never silently concatenated.
- Dry run writes nothing.

### 5.3 Effort and risk

1.5 weeks. Risk: the concat demuxer's "same codec parameters" requirement is
stricter than "same extension" (MP3 with different sample rates is a classic
failure), which is why `compat.py` probes every input instead of trusting the
extension.

## 6. F-E6 — Channel utilities (new tool `channel_tools`)

### 6.1 Design

Pure DSP in one shared module so a future Refinery stage or F-M3 can reuse it.

`audio_suite_shared/channel_ops.py`, operating on `(frames, channels)` float
arrays with the existing `audio_conversion` packing:

| Operation | Rule |
|---|---|
| `mono_mean` | `0.5 * (L + R)` |
| `mono_minus3db` | `0.5 * (L + R)` then `-3 dB`? **No:** the -3 dB rule is `(L + R) / sqrt(2)` normalised so a correlated centre keeps its level — implement as `(L + R) * 0.7071` and document it, with the two rules distinguishable in a test |
| `dual_mono` | copy one channel to both |
| `invert_phase` | `-1.0 * L`, `R`, or both |
| `ms_encode` | `M = (L + R) / 2`, `S = (L - R) / 2` |
| `ms_decode` | `L = M + S`, `R = M - S` |
| `width(percent)` | mid/side, `S *= percent/100`, decode |

Exceptions: an operation that needs stereo on a mono file refuses with a named
reason; an operation that needs a single channel on a multichannel file refuses
rather than picking one.

Tool surface: `channel_tools/` package with CLI, GUI (operation dropdown,
parameters, dry-run), results and the same registration set.
`tool_id = "channel_tools"`, `pyw = Channel_Tools.pyw`.

### 6.2 Acceptance and tests

- Synthetic per-channel fixtures (left = 1 kHz, right = 200 Hz): each operation's
  per-channel RMS and phase measured, not read back from the settings.
- M/S round-trip: `decode(encode(x))` equals `x` **sample-for-sample**
  (max absolute error 0 with float64 internal, <= 1 LSB after packing).
- Width 0 % equals mono sum; 100 % is unity within 0.01 dB; 200 % doubles the
  side energy within 0.1 dB.
- Width > 100 % that would clip is clamped and reported; a dry run names the
  rule it would apply.
- Depth and sample rate preserved.

### 6.3 Effort and risk

1-1.5 weeks. Risk: the two mono rules are easy to conflate and both "look
right" on a correlated centre; the tests must use an uncorrelated L/R pair where
the two rules differ measurably.
