## 2. WP-5 — `audio_suite_shared/audio_probe.py`

### 2.1 Shape

New module with three frozen dataclasses and a documented decode policy:

```python
@dataclass(frozen=True)
class StreamInfo:
    container: str          # from ffprobe format_name
    codec: str
    sample_rate: int
    channels: int
    bit_depth: int | None   # None for lossy
    duration_sec: float
    bitrate_kbps: int

@dataclass(frozen=True)
class LevelMetrics:
    sample_peak_dbfs: float
    true_peak_dbtp: float
    crest_factor_db: float

@dataclass(frozen=True)
class LoudnessMetrics:
    integrated_lufs: float
    loudness_range_lu: float
    true_peak_dbtp: float
    threshold_lufs: float
```

Public functions (each typed, each raising the suite's typed errors):

- `probe_stream(path) -> StreamInfo` — one `ffprobe -show_streams -show_format
  -print_format json` call, parsed defensively, cached per `(path, mtime, size)`
  for the lifetime of a batch via an explicitly passed cache or a module
  `lru_cache`-free helper (no unbounded global cache).
- `decoded_duration(path) -> float`.
- `measure_levels(path) -> LevelMetrics` — sample peak from decoded samples;
  true peak from FFmpeg's oversampled `astats`/`ebur128` field, whichever the
  migrated call site used.
- `measure_loudness(path, *, target=None) -> LoudnessMetrics` — EBU R128 via the
  exact filter chain the migrated module used.
- `measure_album_loudness(paths) -> LoudnessMetrics` — the concat-demuxer
  measurement ReplayGain already performs, moved, not reimplemented.

**Decode policy, written in the module docstring and tested:**

- All probes run through `audio_suite_shared.secure_subprocess.run_secure_subprocess`
  (the Bandit boundary and the timeout live there), never a bare `subprocess`.
- `ffprobe` for stream metadata; `ffmpeg -f null -` for decoding; no pydub in
  the probe path.
- Sample rate conversions are explicit: the filter chain states its sample rate
  (`-ar 48000` where the legacy call site used it) rather than inheriting the
  source's rate.
- Bit depth is reported only for integer-PCM containers; a FLAC's declared depth
  comes from the stream, and WAV/AIFF depth rules stay in `audio_formats`.
- Unsupported/read-only containers are refused before probing with the matrix's
  reason; a probe must never "succeed" on a container the suite cannot write.

### 2.2 Migration order and the equality gate

**WP-5.1 — ReplayGain only (must land).**

1. Add the probe with the FFmpeg arguments copied *verbatim* from
   `replaygain_analyzer/core/ffmpeg_metrics.py` (`get_metrics`'s `ebur128`
   invocation and `measure_album_loudness`'s concat list). Do not "improve" the
   filter chain in the same change.
2. Replace `get_metrics`/`measure_album_loudness` with thin adapters that call
   the probe and keep their current return tuple
   `tuple[float | None, float, float | None]`. Keeping the adapter is what makes
   the change reviewable and reversible.
3. Equality test: for every file in the fixture corpus plus the generated tone
   set, `probe` and the HEAD implementation agree within **0.05 dB** loudness /
   **1 ms** duration / **0.05 dB** peak. Run the HEAD implementation from a
   frozen copy inside the test fixture (a small `_legacy_metrics.py` under
   `replaygain_analyzer/tests/`), not from git history, so the test keeps
   meaning after the code moves.
4. Cross-tool test: `replaygain_analyzer` measurement, normaliser measurement and
   the probe agree within **0.1 dB** on the same file. This is the audit's
   acceptance criterion and the thing users actually notice.

**WP-5.2 — Audio Normalizer (expected in this release, cuttable).**
Same pattern for `audio_normalizer/core/loudness.measure` and
`parse_output_true_peak`. `parse_output_true_peak` is a parser other tests call
directly; keep it and have it delegate.

**WP-5.3 — Recorded but deferred.** `audio_refinery/core/measure.py` (which
measures decoded `AudioSegment`s and therefore needs a different seam),
`audio_enhancer/core/ffmpeg_io.py`, `music_format_converter/core/ffmpeg_params.py`
(parameter construction, not measurement), `audio_suite_shared/lossless_gain.py`
and `analysis_loader` (decode + degenerate-audio guard, already the single
entry point for analysis). Each gets a row in the §10 decision log with the
reason it is a different shape. Migration happens in the release that needs it:
F-E1/F-S7 (album loudness, QC) consume the probe rather than adding a seventh
path.

### 2.4 Acceptance

- Decoded per-file duration, sample peak and integrated loudness equal HEAD
  within the stated tolerances on the corpus.
- Album measurement equals HEAD within 0.05 dB on an uneven album fixture.
- A read-only container is refused with a named reason and no FFmpeg write.
- No new direct `subprocess` import; `tests/test_subprocess_boundary.py` green.
- Suite time budget: the equality suite adds no more than ~60 s (reuse one
  session-scoped corpus; do not copy the BPM corpus).

### 2.5 Effort and risk

1.5-2 weeks for 5.1 + 5.2. Medium-high: the numbers are the product's promises.
Two traps: (a) FFmpeg version differences in `ebur128` rounding — pin the
tolerance and record the FFmpeg version in the test's skip reason if it drifts;
(b) an equality test that re-reads the probe's own output proves nothing, so the
legacy implementation must stay in the fixture.

## 3. WP-6 — One tag layer (C-M2)

### 3.1 Design

New `audio_suite_shared/tag_field_engine.py` (name chosen to avoid colliding
with `tag_helper_writer`, which is single-field):

- `FieldRule` describes one canonical field: canonical name, per-container frame
  or `TXXX` key, value transforms (slash-genre split/join, track/disc
  `n/total`, comment encoding), and whether it is readable/writable.
- `FIELD_RULES: tuple[FieldRule, ...]` is the single mapping table. It is built
  from `tag_helper_base.EDITABLE_FIELDS` plus the extra keys
  `tag_field_updater/core/processor.py` writes today (its `TXXX` names and
  filename-pattern fields). **Enumerate them from the code before writing the
  table**, because the audit is explicit that these rules are tool-specific and
  must be preserved exactly.
- `TagFieldEngine(path)` opens a `BaseTagHandler` through
  `TagHandlerFactory.for_extension` and offers:
  `read_fields()`, `write_fields(mapping, *, dry_run)`, `diff(mapping)`,
  `raw_updates()`, `delete_fields()`. It never touches mutagen directly; the
  handler does the container work, so the FLAC `.tags` rebinding trap stays
  fixed in one place.
- Unsupported format: raise `AudioTagError` with the matrix's reason
  (`format` not tag-writable or no handler). Never fall back to a different
  container.

`tag_field_updater/core/processor.py` becomes a consumer: its mutagen imports
disappear, and its transformation logic (`core/transformation_rules.py`, which
must stay pure and Tk-free) produces a field mapping the engine applies.
`metadata_scrubber` keeps its raw-frame path and gains a module docstring note
plus a test asserting the exception, because it must preserve arbitrary frames
the facade does not model.

### 3.2 Cross-tool equality test

`tests/test_tag_equality_across_tools.py`:

- For each of `.mp3`, `.flac`, `.m4a`, `.wav` (and `.wma` if WP-1 completed it):
  write the same nine-field edit through `tag_editor`'s processor and through
  `tag_field_updater`'s processor into two copies of the same source file.
- Assert after reloading with mutagen: every canonical field equal, every raw
  `TXXX`/Vorbis/MP4 atom equal, artwork bytes equal, and the undo snapshots
  record the same pre-edit values.
- Assert **unsupported formats are refused identically** by both tools, with the
  same message token.
- Compare decoded tags, not file bytes: container padding and frame ordering
  legitimately differ between two writers, so a byte comparison would fail for
  the wrong reason and invite a `# noqa`.

### 3.3 Files

| File | Change |
|---|---|
| `audio_suite_shared/tag_field_engine.py` (new) | `FieldRule`, `FIELD_RULES`, `TagFieldEngine` |
| `tag_field_updater/core/processor.py` | Consumer; direct mutagen imports deleted |
| `tag_field_updater/core/transformation_rules.py` | Stays pure; feeds the engine |
| `tag_editor/core/processor.py` | Routes its writes through the engine (or documents why it already matches) |
| `audio_suite_shared/tag_helper_base.py` | `EDITABLE_FIELDS` documented as the engine's canonical set |
| `metadata_scrubber/core/scrubber.py` | Docstring note only (raw-frame exception) |
| `tests/test_tag_equality_across_tools.py` (new) | The 4-5 container equality lock |
| `tag_field_updater/tests/*` | Existing field-mapping tests kept; they are the rules lock |

### 3.4 Acceptance

- Same edit, same tags on four containers through two tools.
- Dry run writes nothing: file `st_mtime_ns` and decoded tags unchanged.
- Every unsupported extension refused with the standard message and no partial
  write.
- `tag_field_updater`'s existing tests pass unedited except for imports that
  named mutagen internals; any test that must change is a signal the mapping
  moved, and the change is justified in §10.

### 3.5 Effort and risk

2-4 weeks. Medium. The mapping rules are the risk, not the plumbing. Two
specific traps:

1. **ASF/`.wma`.** `tag_field_updater` currently claims it; the shared factory
   has no ASF handler. WP-1 decides whether `.wma` is tag-writable. If it is,
   the ASF handler lands here and the equality test includes `.wma`. If not, the
   refusal is a user-visible regression and moves to `2.5.0` with a CHANGELOG
   bullet — it cannot hide inside a patch.
2. **`.aac`/ADTS.** No tag container; the engine must refuse writes while the
   converter may still produce the file. That is a `tag_writable=False` matrix
   row, not a special case in the engine.
