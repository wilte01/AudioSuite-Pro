## 1. The idea, and the bar it has to clear

Every rival in this space ships presets. A preset is a claim nobody can check:
"Warm", "Punchy", "AI mastering". The Refinery already does more than a preset —
each stage's own line reports what it measured (`hum=on 60 Hz auto, 3 harmonics,
24 dB above floor`, `profile=auto 12.4-12.8 s at -62 dBFS, trial 0.0 dB`,
`Max 4.1 dB reduction (mean 1.8 dB), -13.9 LUFS / -1.6 dBTP`) — but the
**settings that produce those numbers are still typed by a person**.

Best Audio's claim is testable, which is the whole point:

> **Your stages, your preset, your targets — unchanged. Tick Auto on a stage and
> the parameters you would have guessed are measured from the file instead;
> every decision names the measurement behind it, and the written result is
> re-measured.**

Three properties, one work item each:

* **Measured** — the decision comes from this file's own audio (BA-2, BA-3).
* **Auditable** — the decision is written down with its evidence (BA-5).
* **Verified** — the written file is measured again, and the run says whether it
  achieved what it claimed (BA-6).

### 1.1 What Best Audio is not

* It is not a second pipeline, a new DSP stage, a "sound" or a genre preset.
* It is not a replacement for manual settings, for the stage presets, or for the
  seven stage panels.
* It is not a guess at loudness: the delivery target is a decision the user
  makes, and Best Audio never moves it.
* It does not "restore" bandwidth, de-clip, de-ess or de-noise content it cannot
  measure. A lossy source's missing top octave is **reported**, never boosted.

## 2. The additive contract — what Best Audio may never do

This is the load-bearing section. Every rule is a test in BA-9, and any proposed
change that violates one is a plan amendment, not an implementation detail.

| # | Rule | How it is locked |
|---|---|---|
| A1 | **Never** switches a stage on or off. Enablement stays the user's or the preset's. | `StageConfig` toggles are read, never written, by the decision module; a test asserts the toggles are unchanged after a decision. |
| A2 | **Never** changes an enhancement preset name. Auto fills `Custom` fields only, and is inactive while the preset is `Mild`/`Moderate`/`Aggressive`. | Decision test: named preset ⇒ `enhance` decision inactive, fields untouched. |
| A3 | **Never** changes delivery settings: target LUFS, true-peak ceiling, loudness range, album mode, exact trim range or copy mode. | Decision test: all five fields identical before/after. |
| A4 | **Never** hides, deletes or replaces a control. A manual value is preserved while Auto is on, and restored, editable, the moment Auto is unticked. | GUI test: type a value, tick Auto, untick, assert the value is back and the widget is editable. |
| A5 | **Never** changes the broadband **engine** (`spectral`/`neural`) or the 16-bit opt-in. | Decision test; a neural run's report says the broadband half was left to the user. |
| A6 | **Never** runs unasked. Every point of entry defaults to no automation. | Settings, CLI and Driver tests assert the empty default. |
| A7 | **Never** writes when a stage's own detector finds nothing — the no-op rule (`audio_refinery/core/pipeline.py:281`) still decides. | Existing no-op tests keep passing with Auto on; one new "clean master stays byte-identical" test. |
| A8 | **Never** makes a file worse. Post-write guardrails (BA-6) flag a violated claim as a caveat. | Guardrail test with a deliberately wrong plan. |
| A9 | **Never** raises from a measurement. A failed measurement disables that stage's Auto with a reason. | Injected-failure tests per measurement seam. |
| A10 | **Never** silently disagrees with what it displays. Values shown as "measured" carry the file and time they came from. | GUI test asserts the caption names the file. |

A stage whose Auto computes "nothing to do" leaves the file untouched; it never
flips the stage's own switch. With Auto off everywhere, argument lists, presets,
reports and bytes are unchanged (the regression item in BA-9).

### 3.2 What is genuinely missing

1. **A per-file decision layer.** Nothing in the tree chooses a stage's numbers
   from the file; the pipeline applies exactly what the window holds.
2. **Click detection without repair.** `declick_audio` returns repaired audio;
   there is no way to ask "how many clicks, how wide" without also paying for
   the repair, and no single place that both asks and answers.
3. **Bounded-window spectral tilt.** The only spectral measurement
   (`audio_refinery/core/measure.py`) FFTs the whole signal — unusable per file
   in a batch, and it reports ratios, not bands in dB.
4. **Any record of *why* a stage ran.** The stage lines report *what happened*,
   never the threshold that decided it.
5. **Any check of what the written file achieved.**

### 3.3 What that means for the work

Best Audio adds **no DSP and no new stage**. It is one decision module over
detectors that already exist, one evidence channel, and one verification pass.
That is why it can land as a minor release rather than a new subsystem.

### 4.2 `SourceProfile` (frozen dataclass)

Every field is a measurement, never a decision. `None` means "not measured",
which is different from zero.

```
file_name: str
true_peak_dbtp: float | None
clipped_sample_share: float          # share of samples at |x| >= 0.999
hum: HumProfile | None
noise_window: NoiseWindow | None
noise_floor_dbfs: float              # window's level, else the file's RMS
content_rms_dbfs: float              # the measured segment's RMS
clicks: ClickDetection | None        # count, max_width_ms, wider_defects
head_silence_ms, tail_silence_ms: int
band_energy_db: dict[str, float]     # "sub","low","mid","high" over a bounded window
tilt_high_over_mid_db: float | None
brightness_ceiling_hz: int | None    # highest band above the noise gate
measured_at: str                     # ISO-8601 local time
```

Ten figures the forensics pass can report are deliberately absent - duration,
sample rate, channels, integrated LUFS, loudness range, sample peak, crest
factor, per-channel peaks, DC offset and the low/mid tilt - because nothing
reads them; the level block asks `audio_probe.measure_loudness` for the true
peak alone (D-16). The source path is not stored either: `file_name` is what
every report line and caveat names (D-17).

`ClickDetection` (frozen dataclass in `declicker.py`): `count`, `max_width_ms`,
`wider_defects`. `detect_clicks(audio, threshold, max_width_ms)` returns it;
`declick_audio` keeps its existing signature and result, and detects through the
same helpers so the two can never disagree. D-09 replaced the plan's percentile
width with the widest repaired click, so no percentile is computed or stored.

### 4.3 `StageDecision` and `BestAudioPlan`

```
StageDecision(stage, auto, active, reason,
              evidence: tuple[Evidence, ...], params: dict[str, object])
Evidence(name, value, threshold)     # rendered as "name value (threshold x)"
BestAudioPlan(source: SourceProfile,
              decisions: dict[str, StageDecision],   # six declared stages
              config: StageConfig,                   # the effective config
              caveats: tuple[str, ...],
              skipped_reason: str | None)
```

`plan.config` is a **copy** of the run's config with only the Auto stages'
parameters replaced (`dataclasses.replace` with per-stage param objects rebuilt).
The stage toggles, delivery settings, preset name and engine fields are carried
through untouched — the mechanical expression of contract rules A1–A5.

### 4.4 Where it runs

```
_worker_process → process_file(config)
  integrity pre-flight
  copy-mode guard
  normalise container capability
  _load_source                       ← decoded segment + tags in hand
  >>> best_audio.decide(audio, source_path, config)      ← NEW, once per file
  dry run?  → report the plan's decisions, write nothing
  stages    → each uses the plan's config
  write / normalise / atomic replace
  >>> verify_written(output_path, config, plan)          ← NEW, after the replace
```

Configuring Auto at run start (before the first file) is not sufficient and is
explicitly rejected: parameters must be per file.

### 4.5 The ordering rule (the trap this plan exists to avoid)

Decisions are taken **in chain order, on the signal each stage will receive**:

1. Silence is measured on the decoded source (it is the Trim stage's own
   question).
2. If Trim Auto decides to cut, the slice is applied **in memory** and the
   hum/noise decisions are measured on the trimmed segment.
3. Band energies are measured on the trimmed segment, from a bounded window
   (30 s, centred), never a whole-file FFT.

Measuring noise on the untrimmed source is a defect, not a simplification: a
leading digital-silence stretch is the flattest, quietest window in the file, so
`detect_noise_profile` selects it, the floor reads about −120 dBFS, and Best
Audio enables the gate on the strength of a window that will not exist when the
stage runs. The plan's test suite pins this case explicitly.

### 4.6 Laziness and cost

A measurement is taken only when an Auto stage needs it:

| Measurement | Needed by |
|---|---|
| Head/tail silence | `trim` |
| Click detection | `declick` |
| Hum | `reduce_noise` |
| Noise window + floor | `reduce_noise` (spectral only) |
| Band energies / tilt | `eq`, `enhance` |
| True peak (one `ebur128` pass) | `dynamics` |
| Clipped share | `enhance`, and the run caveat |

With no Auto stage, no measurement runs at all: the extra FFmpeg pass is paid
only by runs that asked for it. The cost claim ("at most one extra FFmpeg pass
per file, plus in-memory detection") is **verified by counting subprocess
invocations** with a monkeypatched counter, not by timing alone (§12).

### 4.7 Failure model

A measurement that raises disables **that stage's** Auto for that file with a
reason (`Auto off: noise profile measurement failed (…); the stage's own
settings were used`), logs at WARNING with `exc_info=True`, and lets the run
continue. A decision layer that can abort a batch would be worse than the
problem it solves. Only a programming error (a bug in the module) escapes, as an
`AudioProcessingError` with `context={"stage": "best_audio"}`.

### 4.8 Interactions with existing behaviour

| Feature | Interaction |
|---|---|
| No-op rule | Unchanged and decisive. If the stage's detector finds nothing, the file is not written. |
| Dry run | Decisions are computed and reported; nothing is written but the reports (run report, decisions CSV). |
| Album mode | Auto remains available; the run **warns** when the measured output drifts from the album target (D-04). |
| Exact trim + copy mode | Unchanged: `check_copy_mode` still refuses a stream copy beside a decoding stage. Auto never changes the trim mode. |
| Neural broadband | Unchanged: the engine and 16-bit opt-in are the user's; Auto computes the hum half and says the broadband half was left alone. |
| Completion registry | Unchanged: only a run that wrote the file marks it done. |
| Undo | Unchanged: the existing snapshot precedes every replace, so an Auto run is as undoable as a manual one (asserted). |
| `has_active_stage` guard | Unchanged: the "at least one stage" guard still reads `REFINERY_STAGES`, never `auto_stages`. |

## 5. Decision rules

Constants live in `audio_refinery/core/best_audio.py`, are declared once, and are
named in the report. Values below are **provisional**; BA-8 calibrates each and
records the measured basis in this plan's decision log (§16). A constant that
cannot be calibrated to a safe margin ships **disabled** (`None`) with the
measurements that stopped it — a defensible outcome in this repository.

| Stage | Evidence | Compute when | Parameters produced | Report line |
|---|---|---|---|---|
| `declick` | click detection at the configured sensitivity and width (`detect_clicks`) | ≥1 click | `max_width_ms = min(configured, widest repaired click)`; sensitivity unchanged | `declick auto: 7 clicks at 0.31, widths to 1.8 ms` |
| `trim` | head/tail silence below the stage threshold | head+tail ≥ 200 ms and ≤ 60 % of duration | `threshold` unchanged, `apply_fade` unchanged, `mode` unchanged | `trim auto: head 0.84 s, tail 1.10 s at -50 dBFS` |
| `reduce_noise` (hum) | `detect_hum` | profile found | `reduce_hum` unchanged (user's), `hum_auto` unchanged, `hum_harmonics = max detected order`, `hum_quality` unchanged | `hum auto: 60 Hz, 3 partials, 24 dB above floor` |
| `reduce_noise` (broadband) | floor + content + window trial | floor ≤ −45 dBFS, floor ≥ 18 dB under content, trial ≤ 1.0 dB, engine is `spectral` | `profile_auto` unchanged, `gate_threshold_db` unchanged | `broadband auto: floor -62 dBFS, 34 dB under content, trial 0.2 dB` |
| `eq` | band energies | sub-30 Hz energy ≥ 6 dB above the 40–100 Hz band **and** no high-pass band already present | one `highpass` band at 30 Hz appended; existing bands never edited or removed | `eq auto: high-pass 30 Hz (rumble 9 dB above the band above it)` |
| `dynamics` | crest, true peak, shelf gains Auto added | predicted peak > delivery ceiling + 0.1 dB and the user's limiter is bypassed | limiter un-bypassed at the delivery ceiling; compressor untouched | `dynamics auto: limiter at -1.5 dBTP (predicted -0.9 dBTP)` |
| `enhance` | crest, tilt, level, brightness ceiling | preset is `Custom` **and** a measured tilt deficit exceeds the calibrated margin **and** the source is not bandwidth-limited | shelf/presence gains lifted by at most +2 dB each, total at most +4 dB | `enhance auto: presence +2.0 dB, high shelf +1.5 dB (HF deficit 4.2 dB)` |
| `normalise` | — | never | nothing | `normalise: your settings (Auto not offered)` |

Notes that remove ambiguity:

* **Declick never escalates.** Auto may only *narrow* the repair width. A click
  wider than the configured maximum is reported (`3 wider defects not
  repaired`), not chased with a wider window — that is how a transient becomes a
  casualty.
* **Trim never adds fades.** Fades are taste, not a measurement.
* **Hum never widens the notch set.** `hum_harmonics` is set to the highest
  *detected* order so the notch cascade matches the file; a manual frequency
  override stays the user's.
* **Broadband is never enabled on a neural run.** The engine is the user's
  (A5), and the neural model is speech-trained and 16-bit; the report says so.
* **EQ is additive.** Auto appends at most one high-pass band and never edits a
  band the user drew.
* **Dynamics never compresses.** Only the limiter, only as a ceiling safety net.
* **Enhance requires `Custom`.** With `Mild`/`Moderate`/`Aggressive` selected the
  decision is `inactive`, the fields are untouched, and the reason names the
  preset. Auto never renames a preset (A2).
* **No fabricated corrections.** `brightness_ceiling_hz` below ~16 kHz marks a
  lossy source; the report says `HF limited to 15.8 kHz — not boosted`, and the
  tilt rule is skipped.

## 6. Evidence and reporting

### 6.1 Per-file line

`result.add_stage("BestAudio", FileStatus.DONE, decision_text(plan))` before the
stage results, so a DONE file's report carries the plan. `decision_text` joins
the active decisions with `"; "` and prefixes `BestAudio: `. An inactive stage
is named only when it was asked for (`enhance inactive: preset 'Moderate' is
yours`).

Skipped files do not print stage lines today (the runner prints one SKIP line),
so the decisions CSV — not the per-file line — is the record for them. That is
stated in the report's own caption, so nobody looks for a line that is not
supposed to exist.

### 6.2 Run report header

The run report is written by `audio_refinery/app.py:771`. Add one line, and
nothing else, to the existing header:

```
Mode: LIVE / DRY RUN — BEST AUDIO: 4 of 6 stages (declick, trim, reduce_noise, eq)
```

With no Auto stage the line reads `Mode: LIVE / DRY RUN` exactly as today, so an
existing report is unchanged (A6).

### 6.3 `refinery_decisions.csv`

Written beside the run report, like the album table (`refinery_album.csv`), for
**every** file including skipped ones, on live and dry runs (D-05). A write
failure is logged at WARNING and never raised — the audio work has already
happened by then.

Columns, in this order:

```
file,status,stage,measurement,value,threshold,decision,parameter
```

One row per file per Auto stage that produced a decision, plus one row per file
where Auto was asked for and did nothing (`decision=inactive`, reason in
`measurement`). Rows are written in `AUTO_STAGES` order, files in run order, so
the file is diffable between runs.

### 6.4 Caveats

`record_caveats("audio_refinery", text)` (the existing channel) carries: a
guardrail violation (BA-6), an album-mode drift warning (D-04), a measured
limitation the user should know (lossy bandwidth, unrepaired wide clicks), and a
measurement failure that disabled an Auto stage.

## 7. Verification and guardrails

After the atomic replace, when at least one Auto stage was active and the file
was written, `verify_written()` measures the output once
(`audio_suite_shared/audio_probe.py:575`) and checks:

| Guardrail | Pass condition |
|---|---|
| True peak | measured ≤ configured ceiling + 0.1 dB |
| Integrated loudness | when a LUFS target ran, `abs(measured - target) ≤ tolerance + 0.5 dB` |
| Clipping | no new clipped samples beyond the source's share |
| Bandwidth claim | if the report claimed no HF boost, the output's band energies show none |

A violation asks one question — *was the plan wrong?* — and answers it without
guessing:

1. Log WARNING with both numbers.
2. `record_caveats` with the file name, the claim and the measurement.
3. Append a `BestAudio` verify stage line: `verify: claimed -14.0 LUFS, measured
   -15.6 LUFS — plan did not achieve its target`.
4. Never delete, rewrite or "correct" the output, and never raise.

The guardrail must be provably able to fail: a test injects a plan whose target
is 2 LU away and asserts the caveat and the line appear.

## 8. Surfaces

### 8.1 `StageConfig` (one declaration)

```python
AUTO_STAGES: tuple[str, ...] = (
    "declick", "trim", "reduce_noise", "eq", "dynamics", "enhance",
)
```

`auto_stages: tuple[str, ...] = ()` on `StageConfig`, validated against
`AUTO_STAGES` (unknown names dropped with a WARNING, order normalised to
`AUTO_STAGES`). `normalise` is deliberately absent: its numbers are delivery
choices (A3), not measurements.

**Single source of truth (D-02).** There is no stored `best_audio` boolean. The
bulk control and `--best-audio` resolve to `auto_stages = AUTO_STAGES`; the
per-stage boxes resolve to individual entries. Two representations of one
decision is how a window and a run come to disagree.

### 8.2 Settings round-trip

* `_to_dict` writes `"auto_stages": list(...)` in `AUTO_STAGES` order.
* `_from_dict` reads it, drops unknown or duplicated names with a warning, and
  reads a missing key as empty, so a settings file written before 2.9.0 keeps
  exactly the pipeline it describes.
* `refinery_settings.default.json` is regenerated from `StageConfig()`;
  `audio_refinery/tests/test_settings.py:174` (byte equality) must stay green.
* The live file remains `~/.audiosuite/refinery_settings.json`.

### 8.3 Presets

`_collect_settings` adds `"auto_stages"`; the preset apply map writes it through
the same validator. A preset saved before 2.9.0 loads with no Auto stages, which
is what it described.

### 8.4 CLI (click, `audio_refinery/cli.py`)

```
--best-audio / --no-best-audio      all six stages (default: off)
--auto-stage NAME                   repeatable, choice of AUTO_STAGES
```

Precedence: an explicit `--auto-stage` list wins over `--best-audio` (the
narrower, more explicit statement). `--no-best-audio` with `--auto-stage` is
accepted and means the listed stages only.

### 8.5 GUI-launch CLI (`audio_refinery/utils/cli_args.py`)

The same two flags, same precedence, validated with `parser.error` on an unknown
name, so a Driver launch and a typed command configure one run the same way.

### 8.6 Master Driver

`build_refinery_args` (`master_driver/runner/arg_builder.py:511`) emits
`--auto-stage <name>` for each entry, in `AUTO_STAGES` order, and emits
**nothing** when the list is empty — so every existing argv is byte-identical.
The Refine tab hosts the same setup panel (`master_driver/ui/refinery_tab.py:36`),
so it gains the checkboxes without per-tab code.

### 8.7 GUI (`audio_refinery/ui/setup_tab.py`)

* A **Best Audio** checkbox above the stage panels: tick ⇒ all six; untick ⇒
  none. Its state is computed from `auto_stages` on every change, never stored
  separately.
* An **Auto** checkbox in each of the six stage headers (right of the enable
  checkbox). `normalise` has none.
* While a stage's Auto is ticked, that stage's manual entries are **disabled**
  with a caption naming the reason (`Auto supplies these for this stage; untick
  Auto to edit`). The values stay in the widgets and come back editable when
  Auto is unticked (A4). Nothing is hidden, collapsed or removed.
* After **Preview decisions** (BA-11), an Auto stage's caption reads
  `Auto — measured: <parameters> (from <file>, <time>)`. Before a preview it
  reads `Auto — measured from each file when the run starts`. A value is never
  shown as if it were the run's without naming where it came from (A10).
* Every programmatic pre-fill — CLI flags, Driver argv, restored settings, a
  preset load — routes through **one** `_apply_auto_stages()` function that the
  checkbox command also calls, per the pre-fill rule. A test asserts each route
  reaches it.

## 10. Test plan and fixtures

**New file:** `audio_refinery/tests/test_best_audio.py` (mirrors
`core/best_audio.py`, per the naming rule). Wiring, GUI, settings, CLI and Driver
locks live in those modules' existing test files, as named above.

**Fixtures are generated, not committed, wherever synthesis is enough** (they are
cheap, deterministic and reviewable):

| Fixture | Construction | Proves |
|---|---|---|
| `hum_tone` | 1 kHz tone −18 dBFS + 60 Hz and its 2nd/3rd partials at −40 dBFS | hum decision and measured notch outcome |
| `his_tone` | tone + white noise at −60 dBFS | broadband decision and floor outcome |
| `clicky` | tone + 1 ms impulses every 0.5 s | declick count, width narrowing, "wider defects" report |
| `silent_edges` | 0.8 s silence + tone + 1.0 s silence | trim decision, and the ordering trap (silence must not become the profile) |
| `clean_master` | 30 s of a committed corpus track (`tests/data/bpm_corpus`) | Auto declines; file byte-identical |
| `lossy_top` | tone plus a hard 15 kHz low-pass | "HF limited — not boosted" |

Rules that need no FFmpeg stay unmarked so they always run; anything that
decodes or measures carries the same `integration` marker the probe tests use.

**Outcome assertions decode the output** and measure it — never the field the
code just wrote (the repository's audio-correctness rule): hum partial energy
down by the asserted margin, noise floor down, click count at or near zero,
leading/trailing silence gone within 50 ms, integrated loudness on target within
tolerance, and per-channel RMS checked so a stereo swap cannot pass.

## 11. Calibration protocol

For each constant:

1. Build the fixture pair that should and should not trip the rule.
2. Sweep the constant across a documented range and record, in the decision log,
   the value at which the "should" case first fires and the value at which the
   "should not" case first fires.
3. Choose the midpoint only when the gap is at least 2× the measurement noise;
   otherwise widen the fixtures, narrow the rule, or ship it disabled.
4. Record the numbers, the fixtures and the date. A threshold without a recorded
   basis is not calibrated, however plausible it looks.

The committed corpus supplies the "real music" side of every sweep, so a
threshold that works only on synthetic tones cannot pass.

## 12. Performance

Two measurements, both recorded in the decision log:

* **Subprocess count:** a monkeypatched counter around the subprocess seam
  proves Auto adds at most one FFmpeg invocation per file (the true-peak pass)
  and none when no Auto stage needs levels.
* **Wall clock:** per-file median over ten files, Auto off versus Auto with all
  six stages, same machine, recorded with the hardware named. The claim in this
  plan is the subprocess one; the timing is reported, not promised.

If the counted invocations exceed one, the lazy table in §4.6 is wrong and is
fixed before the item closes.

## 13. Traps this plan must not fall into

1. **No-op regression** — a clean file must stay byte-identical (A7).
2. **The `MagicMock` config** — tests build a real `StageConfig`; a mock answers
   unset fields with truthy children and passes for the wrong reason.
3. **Measuring before the trim** (§4.5).
4. **Album drift** — per-file tone changes move a track away from the plan's
   gain; measured and warned (D-04).
5. **Two sources of truth** — one stored `auto_stages` (D-02).
6. **A control that writes nothing** — the U-04 class; solved by disabling with a
   stated reason and restoring on untick, not by leaving a live control unused.
7. **An unmeasured performance claim** (§12).
8. **A citation that does not resolve** — `tests/test_plan_citations.py` scans
   every plan dated on or after 2026-11-11, including this one.
9. **The committed default JSON** — regenerate it; the byte-equality test is the
   guard.
10. **A pre-fill route that bypasses the update function** — one function, four
    routes, one test.
11. **An output check that reads internal state** — decode and measure (§7).
