## 2. WP-0 — One DSP model (C-M1)

### 2.1 Change

`audio_suite_shared/dsp_models.py` becomes the only definition.

1. Change `class PresetName(Enum)` to `class PresetName(StrEnum)` (`enum.StrEnum`,
   available at the 3.11 floor). This is the only shape that keeps
   `status == "Mild"`, `json.dumps`, and `f"{preset}"` all rendering `Mild` on
   3.11 through 3.14. A plain `(str, Enum)` mixin — the enhancer's current base —
   renders `PresetName.MILD` in f-strings on 3.14, which is the trap `AGENTS.md`
   records for `FingerprintStatus`.
2. Set `EnhancementParams.output_gain_db` default to `4.0`. Evidence for 4.0:
   the applied path is the enhancer model, so adopting 4.0 is behaviour-neutral
   for every rendered file; adopting 0.0 would silently change Custom-preset
   output. Recorded as decision D-1.
3. Keep `__post_init__` raising `AudioConfigValueError` (the suite's typed
   error). A caller that caught `ValueError` still catches it — `AudioConfigValueError`
   must be confirmed to subclass `AudioSuiteError`; if it does not subclass
   `ValueError`, add a `ValueError` base or keep both call sites catching the
   typed error. **Check before changing:** `audio_suite_shared/exceptions.py`.
4. Add `def preset_text(preset: PresetName) -> str` returning `preset.value`, and
   route every display site through it, so a future enum base change cannot
   alter a label again.

`audio_enhancer/core/models.py` becomes a re-export module:

```python
from audio_suite_shared.dsp_models import (
    PRESETS as PRESETS,
    EnhancementParams as EnhancementParams,
    PresetName as PresetName,
)
```

Redundant-alias form, not `# noqa: F401`: mypy `--strict` requires the explicit
re-export marker and ruff already treats it as one. Do **not** keep a second
`PRESETS` dict "for compatibility"; identity is the point of the item.

`JobStatus`, `AudioFileInfo`, `ProcessingResult` are deleted in WP-3, not here,
so this change stays reviewable.

### 2.3 Tests

- `PRESETS is dsp_models.PRESETS`; `EnhancementParams is dsp_models.EnhancementParams`;
  `PresetName is dsp_models.PresetName`.
- Every preset compared field-by-field against the shared table (guards a future
  re-introduction of a local dict).
- Every `PresetName` member: `f"{member}"`, `str(member)`, `format(member)`,
  `json.dumps(member)` all equal `member.value`.
- `EnhancementParams()` default `output_gain_db == 4.0`.

## 3. WP-1 — One format capability matrix (C-M3)

### 3.1 Design

Extend `audio_suite_shared/audio_formats.py` with a frozen dataclass keyed by
extension. Do not create a second module and leave `audio_formats` as a facade:
this file is the suite's public format vocabulary and 20+ tools import it.

```python
@dataclass(frozen=True)
class FormatCapability:
    extension: str            # ".wma"
    display_name: str         # "WMA"
    pydub_format: str | None  # None => FFmpeg direct
    ffmpeg_encoder: str | None
    ffmpeg_muxer: str | None
    lossless: bool
    readable: bool
    writable: bool
    tag_writable: bool
    depth_codecs: dict[int, str]   # {} unless integer-PCM container
    output_extension: str          # container extension to write
```

`FORMAT_MATRIX: dict[str, FormatCapability]` is the source of truth.
`SUPPORTED_EXTENSIONS`, `READ_ONLY_EXTENSIONS`, `LOSSLESS_EXTENSIONS`,
`COMPRESSED_EXTENSIONS`, `PYDUB_FORMAT`, `_DEPTH_CODECS` and
`is_read_only_extension` become projections of it, keeping their current names
and return shapes.

Codec-name handling: the converter speaks codec names (`aac`, `alac`) while
discovery speaks extensions. Add `CODEC_TO_EXTENSION: dict[str, str]` in the
matrix module (`alac -> m4a`, `aac -> aac` if ADTS is written) and make
`music_format_converter/core/formats.py` derive `LOSSY_FORMATS`,
`LOSSLESS_FORMATS`, `ALL_FORMATS`, `UNSUPPORTED_OUTPUT_FORMATS`,
`OUTPUT_EXTENSIONS` and `is_lossy` from it. Keep every public function name and
signature in that module; its tests are the behaviour lock.

### 3.2 The `.wma` decision (blocking, decision D-4)

Today `.wma` is a converter input and a `tag_field_updater` target (that package
imports `mutagen.asf.ASF` directly), but invisible to every tool that calls
`is_supported_format`. Removing `.wma` from the converter therefore *removes* a
capability and cannot ship in a patch.

Recommended: **complete** it.

1. Verify on the dev host: `ffmpeg -hide_banner -encoders | grep -i wmav2` and
   `ffmpeg -hide_banner -muxers | grep -i asf`. If `wmav2` + `asf` are present,
   the container is writable.
2. Add `.wma` to the matrix as readable, writable, lossy, `tag_writable=True`,
   `pydub_format="asf"` (or `None` with an explicit codec/muxer pair if pydub's
   asf path is unreliable — measure, do not assume).
3. WP-6's engine needs a tag handler for ASF. If `.wma` is advertised as
   `tag_writable=True`, that handler must exist by `2.4.2`; until then declare
   `tag_writable=False` and have writers refuse with the standard message. The
   matrix field is what makes this honest rather than a silent drop.
4. `.aac` (raw ADTS): writable, `tag_writable=False`. The converter already
   warns via `format_info`; the matrix makes the warning a fact rather than a
   note.

If the FFmpeg check fails, fall back to (b): mark `.wma` readable only, keep it
out of `ALL_OUTPUT_FORMATS`, and move the converter-list removal to `2.5.0`
where a behaviour change is allowed. Record which branch was taken in §10.

| File | Change |
|---|---|
| `audio_suite_shared/audio_formats.py` | `FormatCapability`, `FORMAT_MATRIX`, `CODEC_TO_EXTENSION`; existing constants derived; `get_export_args` reads the matrix and **stops falling back to MP3** for an unknown extension — an unknown extension must raise rather than silently write MP3 |
| `music_format_converter/core/formats.py` | Derives lists and maps from the matrix; keeps `detect_format`, `can_convert`, `available_output_formats`, `available_output_formats_for`, `output_extension`, `format_info`, `discover_input_files`, `scan_input_directory`, `ScanResult` |

`get_export_args` currently returns `("mp3", ["-q:a", "0"])` for any unknown
extension. That fallback is the mechanism behind the documented
"silently mislabelled codec" risk. Changing it to raise is a behaviour change
for a caller that passes a bogus extension — audit every caller first
(`pipeline`, `pop_click_remover`, `silence_trimmer`, `audio_conversion`) and add
the refusal test at each consumer seam.

### 3.4 Tests

- Every extension in `SUPPORTED_EXTENSIONS` has exactly one matrix row, and every
  row's `extension` is in `SUPPORTED_EXTENSIONS`. Assert the set is non-empty and
  the count is the expected constant (a scan that finds nothing must fail).
- Every `writable=True` row: encode a 1-second 440 Hz tone, decode it, assert
  container/codec from `ffprobe` and that no silent fallback occurred. Mark
  `integration` and reuse one session-scoped source tone.
- Every `writable=False` row: `get_export_args`/converter path refuses with the

- Converter equivalence: `set(ALL_OUTPUT_FORMATS)` equals the writable codec-name
  projection; `available_output_formats("mp3")` still excludes lossless and
  self.
- Discovery: a `.wma` file in a temp folder is found by
  `music_format_converter.core.formats.discover_input_files` **and** by

## 6. WP-4 — One driver handshake (C-M8)

### 6.1 Design

One grammar, one scanner, one table, in `audio_suite_shared`.

- `cli_helpers.DriverHandshake` (frozen dataclass): `path`, `mode` (`"live"` /
  `"dry"` / `""`), `auto_start: bool`, `auto_end: bool`,
  `clear_logs: bool | None`, `parallel_run: bool | None`.
- `cli_helpers.scan_value_options(argv, value_options)` is the single scanner.
  It walks argv left to right, skips the value after any flag in
  `value_options`, and records positional tokens. Tool option tables come from a
  per-tool `VALUE_OPTIONS: tuple[str, ...]` declared next to that tool's Args
  dataclass.
- `cli_helpers.parse_driver_handshake(argv, value_options, *, positional_index)`
  returns a `DriverHandshake`. `positional_index` covers the tools whose path is
  not argv[1] (`audio_refinery` uses `--source`; `cd_ripper` uses
  `--output-dir`).
- `cli_dataclasses.BaseCLIArgs` gains
  `parse_driver_handshake(cls, argv, value_options)` and applies the result to
  `folder_path`/`live_mode`/`auto_start`/`auto_end`.
- `looks_like_driver_argv` has **one** implementation in `cli_helpers`, keyed on
  the presence of `--live`/`--dry` plus any two of the four handshake tokens; the
  four tool copies become one-line delegates.

Replaced call sites: `cd_ripper`, `file_reorganizer`, `library_stats`,
`spectral_viewer` (`_scan_value_options`); `duplicate_finder`, `restoration`,
`tag_editor`, `tag_field_updater` (`looks_like_driver_argv`);
`album_art_sync` (`_flag_value`).

### 6.2 The contract test is the point

New `tests/test_driver_handshake_contract.py`:

1. A frozen `HANDSHAKE_TOOLS` table: every tool that declares a handshake, with
   its positional index and value options. `get_registry().first_party` must
   cover it exactly — a manifest with no entry fails, so a new tool cannot skip
   the contract.
2. For each entry, a canonical argv built exactly as
   `master_driver/runner/arg_builder.py` builds it (import the real builder with
   a `MagicMock` `AppState` whose vars return known values, so the test cannot
   drift into a hand-written argv) is passed to the tool's real `parse()`, and
   `path`/`live_mode`/`auto_start`/`auto_end` are asserted.
3. For tools with no handshake (`audio_refinery`, `cd_ripper`, and the
   `[]`-returning `stem_separator` case), the table records the reason and the
   test asserts their builder output is parsed by their own flags — not silently
   ignored.
4. Assert the table's size equals the expected count (27 minus the recorded
   exceptions). An empty discovery pass must fail.

A launched-process smoke test for two tools (one enrich, one utility) runs the
real `.pyw` entry with `--dry --no-start --no-end` and asserts the window is
constructed with those states, using the existing hidden-root pattern.

### 7.2 Fault-injection tests

- `audio_suite_shared/tests/test_inplace_failure_surfaces.py`: monkeypatch the
  in-place writer to raise `OSError`; assert the file's outcome is `error` (not
  `skipped`), the message names the file, no DONE payload is published, and
  `run_inplace_dsp_batch` completes the remaining files.
- `audio_suite_shared/tests/test_tag_write_failure.py`: monkeypatch
  `TagHandlerFactory.for_extension(...).write_editable_tag` to raise
  `AudioTagError`; assert the caller reports an error and the undo batch records
  no snapshot for the failed file.
- One test per triage bucket (a)/(b)/(c) proving the *outcome*, not the handler
  shape.

### 7.3 Effort and risk

1-2 weeks, judgement-heavy. Ship only when every production site is in a bucket;
a per-file ignore for "later" is the blanket suppression this repo forbids. If
the window closes first, cut the release without WP-7 rather than shipping a
half-triaged rule with silent exemptions.
