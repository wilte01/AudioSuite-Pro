## 1. The one idea this release rests on

Recursion is cheap here because of a property the suite already has, not because
of anything this plan invents.

`FileDiscoveryMixin.discover_audio_files`
(`audio_suite_shared/file_discovery.py`) is a single flat `os.scandir` that
returns **base names**. Every per-file worker downstream then builds its path as
`os.path.join(dir_path, name)` — verified at sixteen call sites (fourteen inside
the tools, two in the shared workflows) across BPM, Key, Tempo, Mood, Scrubber,
Genre Sync, Stem Separator, Lyrics, Album Genre, the shared in-place DSP
workflow (`audio_suite_shared/inplace_workflow.py:149`) and the shared pools
(`audio_suite_shared/parallel_pool.py:271`).

So if discovery instead returns paths **relative to the scanned root** — for
example `Abbey Road/01 - Come Together.flac` — then `os.path.join(dir_path,
name)` produces a correct absolute path with **no change to any worker, any
callback payload, any undo record or any tag call.**

This is not a proposal; a shipped tool already does exactly it.
`music_format_converter/core/formats.py::_discover_recursive` walks explicitly
and returns relative names, and `music_format_converter/core/file_processor.py:452`
joins them onto `input_dir` unchanged. Its comment states the intent: *"Recursive
discovery keeps each file's relative path so the output…"*. That file is the
reference implementation this plan generalises, and its explicit-`scandir`
recursion (rather than `os.walk`) is also the error-attribution model to copy:
the root re-raises, a nested unreadable directory logs and is skipped.

What changes, therefore, is **one function and its forwarding**, plus one flag
per surface. What does *not* change is sixteen per-file workers.

## 3. Items

### 3.1 REC-1 — Shared groundwork (~1.25 days, not cuttable)

1. `audio_suite_shared/constants.py`:

   ```python
   #: Default for every tool's "Include sub-folders" switch. Off keeps every
   #: existing batch's behaviour byte-identical on upgrade.
   DEFAULT_RECURSIVE_SCAN: bool = False
   ```

2. `FileDiscoveryMixin.discover_audio_files(dir_path, extensions=None, *,
   recursive: bool | None = None)`:
   - `recursive is None` → `DEFAULT_RECURSIVE_SCAN`;
   - flat path unchanged (same `os.scandir`, same base names, same exceptions);
   - recursive path returns **relative paths** joined from the scanned root,
     directories sorted and files sorted inside each, so a walk is reproducible;
   - the scanned root re-raises `PermissionError`/`OSError` as the existing
     `AudioPermissionError`/`AudioDirectoryError`; a nested unreadable directory
     logs a warning and is skipped (the `_discover_recursive` model).
3. `_preflight_discover` gains `recursive` and forwards it; its four callers
   (`audio_suite_shared/parallel_pool.py:86`,
   `audio_suite_shared/parallel_pool.py:207`,
   `audio_suite_shared/inplace_workflow.py:267`,
   `audio_suite_shared/file_processor_base.py:254`) gain a keyword-only
   `recursive` that reaches discovery but **never** reaches `processor_kwargs`
   for the per-file worker.
4. `audio_suite_shared/cli_base.py`: one shared decorator beside `_opt_dir` /
   `_opt_parallel`:

   ```python
   _opt_recursive = click.option(
       "--recursive/--no-recursive",
       "recursive",
       default=DEFAULT_RECURSIVE_SCAN,
       help="Also scan sub-folders (default: off).",
   )
   ```

5. `audio_suite_shared/cli_helpers.py`: register `--recursive` and
   `--no-recursive` in the accepted driver token set (the map near line 58 and
   the token frozenset near line 238), so the Master Driver's handshake parser
   accepts them; each tool's `ACCEPTED_HANDSHAKE` set gains both tokens or its
   parse fails loudly.
6. Fold the two existing walkers into this one implementation:
   `cue_generator.scan_audio_files` and
   `music_format_converter/core/formats.py::_discover_recursive`. Two recursive
   walkers in the tree is already a *Shared Implementations First* violation; a
   third would make it a convention.

**Acceptance**
- Flat mode returns exactly the same list as `3.1.0` for the same directory
  (byte-identical, including ordering where the caller sorts).
- Recursive mode returns relative paths, and `os.path.join(root, name)` on each
  one is an existing file.
- A nested unreadable directory is skipped with a logged warning and the run
  completes; an unreadable **root** raises the existing typed error.

## 4. The switch: default Off, and how it is changed to On

One value, four surfaces, nothing declaring `False` as a literal.

### 4.1 Level A — per run (no code change)

Tick **Include subfolders** on the tool's Setup tab, pass `--recursive` on the
command line, or tick the step's card in the Master Driver. This is the whole
user story for an operator who wants it once.

### 4.2 Level B — sticky on that machine (no code change)

`AnalysisAppBase` builds the variable exactly as it already builds
`parallel_mode`:

```python
self.recursive = tk.BooleanVar(value=bool(
    _suite_config.load_value(self._setting_key("recursive"),
                             DEFAULT_RECURSIVE_SCAN)))
```

`start_processing` persists it beside `parallel_mode`/`max_workers`, so the tick
survives a restart; `_collect_settings`/`_apply_preset` carry it so a saved
preset remembers the choice.

**Asymmetry to respect:** the Master Driver's card variables are deliberately
**not** persisted — every run shows what the batch will actually do, and a
remembered tick would let a batch silently widen its scope. That is precisely why
those variables must be built from `DEFAULT_RECURSIVE_SCAN` rather than a
literal: their "default" is whatever the constant says at launch.

### 4.3 Level C — change the product default (one line, three preconditions)

Edit `DEFAULT_RECURSIVE_SCAN = True`. That is genuinely one line **only if**:

1. **REC-6's guard test exists.** Otherwise Level C decays into a twelve-site
   edit the first time someone writes `value=False`.
2. **The exception set is declared.** `cue_sheet` (D-18) and — depending on Q-2 —
   `album_genre` and `art` must stay flat for semantic reasons. The constant is
   the default for a declared list, not a blanket.
3. **The saved-value consequence is accepted and documented.** `load_value(key,
   DEFAULT_RECURSIVE_SCAN)` returns the **stored** value, so any machine where the
   user has run the tool once keeps its saved `False`. Flipping the constant
   therefore reaches fresh installs and never-touched tools only. That is the
   correct behaviour — an explicit choice by the user outranks a new product
   default — and it belongs in the release note rather than in a migration.
   Forcing existing installs would need a config-version sentinel; this plan does
   not propose it.

### 4.4 What a flip visibly changes (and why it is not free)

- Every run report gains `Sub-folders: yes`, so report golden tests and the
  sample output in the guides move.
- A Master Driver batch over an album root stops meaning "these tracks" and
  starts meaning "every track beneath this folder". For BPM, Key, Tempo and Mood
  that is harmless; for Audio Refinery it changes album-gain grouping, which is
  audio-correctness territory. This is the strongest argument for keeping driver
  batches explicit — and for shipping Level C as a deliberate release decision,
  never as a drive-by default change.

## 5. Acceptance and tests (release-level locks)

1. **Relative paths.** Recursive discovery returns root-relative paths;
   `os.path.join(root, rel)` exists for every one; the sort order is stable
   across two runs.
2. **Error attribution.** An unreadable nested directory logs and is skipped; an
   unreadable root raises the existing typed error. Both asserted, and the
   non-empty result set asserted, so an empty scan cannot pass vacuously
   (`PLAN_2026-11-03_audit_sequencing.md` §4).
3. **Flat mode is untouched.** For every REC-2 tool, a flat run produces the same
   list, report and tags as `3.1.0`. Existing basename assertions stay green
   unchanged.
4. **Relative path surfaces.** A recursive run's report line and progress line
   carry the relative path; the header carries `Sub-folders: yes`.
5. **Refinery by measurement.** Decoded per-folder RMS/loudness proves two albums
   got two plans. Never read back the plan object.
6. **Mood parity.** REC-5's tree test above, asserted on tags written to disk.
7. **Default lock.** REC-6's guard test fails if any surface stops reading the
   constant.
8. **Pre-fill.** A recursive checkbox set from a preset, a CLI flag or a restored
   config asserts the **narrowed/expected** state — the `AGENTS.md` pre-fill rule.
   (These are `BooleanVar`s read at run time, so the derived-widget trap does not
   bite today; it would the moment a tool adds a derived "N files found" count,
   which is why the test states the rule rather than the current luck.)
