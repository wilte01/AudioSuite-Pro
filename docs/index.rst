AudioSuite-Pro documentation
============================

AudioSuite-Pro is a suite of audio tools driven through one Click CLI and one
Master Driver GUI. This page is the front door: every user guide, reference
document and the shared package's API reference hang off it.

If you are installing the suite for the first time, start with the
`README <../README.md>`_ — it covers prerequisites, the one-command smoke test
and the platform support matrix. What changed in this release is in the
`changelog <../CHANGELOG.md>`_.

User guides
-----------

Every tool has its own user guide. They are Word documents because that is what
each program's Help button opens; each one is rendered from a Markdown source
by the shared ``utilities/build_user_guides.py`` renderer, so the prose is
reviewable as text and the artefact cannot drift from it.

Suite-wide guides
-----------------

* `Security in AudioSuite-Pro <user/security.md>`_ — encrypted API keys and how
  to recover them, safe file selection, and what each security message means.
* `Logging system guide <../user_guides/suite_overview/LOGGING_SYSTEM_GUIDE.docx>`_
  — where each program writes its log, what the levels mean, and how to read a
  failing run.
* `New-user presentation <../user_guides/suite_overview/AudioSuite-Pro_New_User_Presentation.pptx>`_
  — a slide walkthrough of the suite.
* `Installer build guide <../packaging/BUILD_INSTALLER.md>`_ — building the
  Windows installer from a checkout.

Reference
---------

* `CLI commands reference <../user_guides/reference/CLI_Commands_Reference.md>`_
  — every ``audiosuite`` command, its flags, and a headless/scripting section.
  Its flag names and defaults are locked against the real click commands.
* `Message guide <../user_guides/reference/AudioSuite_Message_Guide.docx>`_ —
  every user-facing message and what to do about it.
* ``audiosuite --json-schema`` — the machine-readable output contract, printed
  by the CLI itself, with one recorded success and failure document per command.

Developer documentation
-----------------------

* :doc:`api` — the API reference for ``audio_suite_shared``, generated from the
  package's docstrings. Every shared module is rendered, and malformed RST in a
  docstring fails the suite.
* :doc:`plugins` — the plugin system: manifest, extension points, and a first
  plugin.
* `Contributing <../CONTRIBUTING.md>`_ — the gate, the test conventions, and the
  checklist for registering a new tool.
* `AGENTS.md <../AGENTS.md>`_ — the repository's instruction file: the rules the
  gate enforces, and the domain traps worth knowing before editing DSP code.

Decision record
---------------

The ``PLAN_*.md`` and ``AUDIT_*.md`` files at the repository root are the
project's decision log: each records what was decided, the evidence behind it and
what was deferred. They are history, not instructions — the rules that still
apply live in ``AGENTS.md`` and ``CONTRIBUTING.md``.

* ``PLAN_docs_consolidation.md`` — the current plan: consolidating this
  documentation into as few formats as possible.
* ``AUDIT_2026-10-06_suite_report.md`` — the most recent full audit.
* `CHANGELOG.md <../CHANGELOG.md>`_ — the shipped history, by release.
