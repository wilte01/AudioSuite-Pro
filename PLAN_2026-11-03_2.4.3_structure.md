## 2. WP-8 — One GUI shell, three tools

### 2.1 Design decision: a new base, not a fourth orphan

`tool_app_base.AnalysisTagToolApp` and `NoisePopToolApp` are analysis-shaped:
they own a folder, a run of N files, a results table and analysis callbacks.
`BaseSuiteApp` owns bootstrap only. The three target tools are **batch
transformers** with a source/output pair (or a folder plus an output mode), a
staged pipeline and their own settings collection.

Add `audio_suite_shared/suite_app.py::SuiteApp` that composes the existing
pieces rather than inventing new ones:

```python
class SuiteApp(UIHelperMixin):
    # supplied by the tool
    title: str
    guide_name: str
    program_name: str
    tab_builders: tuple[Callable[[tk.Frame, SuiteApp], tk.Widget], ...]
    def collect_settings(self) -> object: ...
    def start_run(self, settings: object) -> None: ...
    def build_run_controls(self) -> list[tk.Widget]: ...
    # owned by the shell
    def _build_ui(self) -> None: ...   # notebook, header, help, run strip,
                                        # progress/status, results tab, log path
    def _on_progress(self, **kw: Any) -> None: ...
    def _on_complete(self, **kw: Any) -> None: ...
    def _on_error(self, message: str) -> None: ...
```

Rules that make this safe:

- `SuiteApp` owns the notebook and the results tab through
  `ui_common.build_results_tab`; a tool supplies tab builders and nothing else
  about layout.
- Progress/complete/error handlers keep the `AGENTS.md` callback contract:
  catch-all `**_extra: Any` on the open seams, a single `message` on `on_error`,
  widget writes marshalled with `self.root.after(0, ...)`.
- A tool may keep its own `_build_ui` fragment **inside a tab**, never around the
  shell.
- Migrate only tools where the shell genuinely fits. A tool that cannot adopt it
  without a second shell is not a WP-8 target; the audit's three named tools are
  the ones with the largest duplicated composers.

### 3.2 Method (the only method that is safe here)

1. **Lock behaviour before moving anything.** For each module, identify the
   tests that assert decoded audio or a written report, and add a missing lock
   where the module is audio-critical (`file_processor_base` in-place path).
2. **Move, do not rewrite.** Cut the functions, keep names and signatures, and
   leave a public facade module that imports them with the redundant-alias form
   (`from .ui_tabs import build_results_tab as build_results_tab`), so all
   current importers keep working and mypy stays happy.
3. **One module per commit, one commit per gate run.**
4. **No behaviour change inside a split.** If a split reveals a defect, fix it
   in its own commit with a regression test and log it — do not fold it into the
   move.
5. **Re-diff every touched block by eye** (`AGENTS.md`, *Never Lose a Rule to a
   Scripted Edit*). A scripted extraction that de-indents a loop body compiles
   and passes ruff; the behaviour tests are the only guard.
6. **Check for a stale `.pyc`** after any break-and-restore, because a
   same-length edit in one mtime tick is invisible to Python.

### 3.3 Complexity ceiling

Add `PLR0912` (too many branches) and `PLR0915` (too many statements) to
`[tool.ruff.lint] select`, configured just above the **post-split** maxima, so
new monsters fail review and the four named offenders are reduced rather than
grandfathered:

- `_collect_tags_to_preserve` (135/75) splits into per-container collectors in
  `metadata_scrubber` — this is the one function the split work must actually
  restructure, not just move.
- `_apply_preset` (96/40) is split along preset-vs-custom validation.
- `library_stats/cli.py::stats` (187/40) is split into option assembly, scan
  delegation and report rendering.
- `asx_stub.parse_stub_bytes` (111/39) is split per metadata group.

Where a function legitimately stays long, use `# noqa: PLR0912 - <reason>` with
a named reason and a plan row; do not raise the global threshold to clear it.

### 3.4 Verification

- Every existing behaviour test kept; the only acceptable count drop is a test
  that covered deleted code (WP-3) or a duplicate helper retired by a split, and
  each is named.
- Decoded outputs and written reports identical before/after on the fixture
  corpus (compare CSV/JSON report content, not formatting).
- Import-graph test: every public name still resolves from its old path
  (`tests/test_public_api_paths.py`), with a non-empty expected set derived from
  a frozen list.
- `python -m mypy .` green after each commit, not just at the end.

### 3.5 Effort and risk

3-4 weeks. Medium. The in-place workflow is audio-critical: split it last, with
the fault-injection tests from WP-7 already in place.
